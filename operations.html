OWNER REVIEW · NOVEMBER 2, 2026

Keep it useful
after launch.

A restaurant website is only as reliable as its menu, hours, show listings, and contact routes. This is the operating plan to agree before an official launch.

Current status: a public, independently hosted redesign preview. The restaurant’s official domain and systems have not been changed. The preview is marked noindex; it is still accessible to anyone with its URL.

What is already in the working preview

  • A complete, readable HTML menu, enhanced with search, categories, and shareable links.
  • A music finder using the restaurant’s existing public event feed. It removes ended shows, checks for changes while the page is open, labels source freshness, and provides dated saved listings and an official-calendar link when the feed fails.
  • A show plan with dinner, phone, directions, a shareable URL, and a calendar reminder.
  • Today’s posted hours in Grapevine’s time zone, plus full weekly hours and visit information.
  • Existing SpotOn, telephone, directions, newsletter, and social destinations. Group inquiries prepare an email for the guest to review and send; they are not server submissions.

The change process

  1. Confirm the facts. Reconcile prices, ingredients, hours, and show details with the team. The Chili Verde ingredient conflict between the PDF and checkout is a concrete example that needs owner resolution.
  2. Preview the update. Review the changed menu or show on a phone-sized page and in a desktop browser. Check empty states as well as the usual path.
  3. Run the release checks. The repository includes menu-search, live-feed, and calendar/time-zone regression checks. Verify internal links and the primary guest journeys.
  4. Publish an identifiable version. Keep source history, a rollback point, and a release note. Verify the public URL, event-feed status, menu result links, and external handoffs after publishing.

Before replacing the official domain

  • Approve the content, design, photo/brand use, integrations, fee, scope, and support period.
  • Keep or deliberately redirect existing URLs. Carry forward appropriate analytics and correct Restaurant/MusicVenue/Event metadata; use Grapevine’s actual time zone.
  • Verify actual form delivery, checkout handoff, and phone/directions behavior with authorized tests. The preview audit does not prove completed orders or reservations.
  • Test physical phones, major browsers, keyboard navigation, screen-reader flows, zoom, contrast, and representative connection speeds.
  • Document ownership, access, backups, update responsibilities, and rollback. Provide training using an actual menu or show update.

Measure the work after launch

Agree a baseline before migration and a comparable review window afterward. Measure whether guests can find a dish and price, identify a suitable show, and reach directions or a call. Approved analytics can count ordering handoffs, calendar downloads, and show-link sharing; those actions are not completed purchases or visits. Review errors and owner update effort alongside the numbers. No analytics collector has been added to this preview.
